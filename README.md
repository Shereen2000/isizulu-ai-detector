# isiZulu AI-Detection Classifier

This is a binary text classifier that tells you whether a piece of isiZulu text was written by a human or generated by an AI. It's fine-tuned on top of AfroXLMR-Large — an XLM-RoBERTa variant pre-trained specifically with African languages in mind, which makes it a much better fit for isiZulu than a generic multilingual model.

Label `0` means human-written. Label `1` means machine-generated.

---

Training ran for 4 epochs (about 22 minutes on an RTX 5090) before early stopping kicked in. The best checkpoint came out of epoch 2.

## How It Works

The base model is **AfroXLMR-Large-29L**, a 559.9M parameter transformer pre-trained on African languages. It gets loaded, a classification head is attached, and then it's fine-tuned on the isiZulu human vs machine dataset.

At inference, you feed it a piece of isiZulu text and it returns a prediction: `0` (human) or `1` (machine). The model also outputs confidence scores (logits) which `test.py` uses to compute ROC-AUC.

| Property            | Value         |
|---------------------|---------------|
| Architecture        | XLM-RoBERTa   |
| Hidden size         | 1024          |
| Attention heads     | 16            |
| Transformer layers  | 24            |
| Parameters          | 559.9M        |
| Vocabulary          | 250,002 tokens|
| Max position embeds | 514           |

## Dataset Format

Each dataset file is a `.jsonl` — one JSON object per line:

```json
{"text": "Umculo udlala indima ebalulekile", "label": 0}
{"text": "Ingxenye yesibili yezinhlobo zezilimi", "label": 1}
```

| Split | Total  | Human (0)     | Machine (1)   |
|-------|--------|---------------|---------------|
| train | 16,377 | 8,207 (50.1%) | 8,170 (49.9%) |
| eval  | 1,991  | 994 (49.9%)   | 997 (50.1%)   |
| test  | 2,022  | 1,013 (50.1%) | 1,009 (49.9%) |

The splits are balanced, so there's no class imbalance to worry about.

## Training Configuration

These are the hyperparameters used. If you want to experiment you can change them directly at the top of `scripts/finetune.py`.

| Hyperparameter          | Value              | Where to change            |
|-------------------------|--------------------|----------------------------|
| Max sequence length     | 512 tokens         | `MAX_LENGTH` in finetune.py |
| Batch size (per device) | 8                  | `BATCH_SIZE` in finetune.py |
| Gradient accumulation   | 4 steps (eff. 32)  | `GRAD_ACCUM` in finetune.py |
| Learning rate           | 2e-5               | `LEARNING_RATE` in finetune.py |
| LR scheduler            | Cosine             | `lr_scheduler_type` in TrainingArguments |
| Warmup ratio            | 0.1                | `warmup_ratio` in TrainingArguments |
| Weight decay            | 0.01               | `weight_decay` in TrainingArguments |
| Max epochs              | 5                  | `EPOCHS` in finetune.py    |
| Early stopping patience | 2 epochs           | `EarlyStoppingCallback` in finetune.py |
| Best model metric       | F1 (binary)        | `metric_for_best_model` in TrainingArguments |
| Mixed precision         | fp16 (if CUDA)     | auto-detected              |
| Seed                    | 42                 | `SEED` in finetune.py      |

If you're running on a machine with less VRAM, the first things to reduce are `BATCH_SIZE` and `MAX_LENGTH`. Dropping batch size to 4 and keeping gradient accumulation at 4 gives you an effective batch of 16 instead of 32 — workable on most consumer GPUs.

## Running the Project

There are three ways to run this depending on your setup. If you just want to run inference on the trained model, **Option 1 or 2** is the easiest. If you want to retrain or change configs, all three options work.

---

### Option 1 — Pull the Docker Image (Easiest)

This is the fastest way to get going. The image is already built and hosted on GitHub Container Registry. You just pull and run it, no setup needed.

**Requirements:**
- Docker
- [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html) (for GPU support)
- NVIDIA driver ≥ 550

```bash
# Pull the image
docker pull ghcr.io/tumisomokautu/zulu-classifier:latest
```

**Recommended: interactive shell**

Start a shell inside the container and run scripts manually. This keeps everything in the same container, so fine-tuned weights are immediately available to the test script without any volume mounting:

```bash
docker run --gpus all -it ghcr.io/tumisomokautu/zulu-classifier:latest bash
```

Then inside the container:

```bash
# Step 1 — fine-tune (takes ~20+ minutes on a good GPU)
python3 scripts/finetune.py

# Step 2 — evaluate
python3 scripts/test.py
```

The model weights download automatically on first run.

**Alternative: run a script directly without entering the shell**

You can also pass the script as a command to `docker run` and skip the interactive shell:

```bash
# Fine-tune only
docker run --gpus all ghcr.io/tumisomokautu/zulu-classifier:latest python3 scripts/finetune.py

# Evaluate only
docker run --gpus all ghcr.io/tumisomokautu/zulu-classifier:latest python3 scripts/test.py
```

Note that each `docker run` creates a separate container, so running fine-tune and test this way means the fine-tuned weights won't carry over, use the interactive shell approach above if you want to run both in sequence.

**Saving output to your host machine**

Output written inside the container is lost when you exit. Mount a volume to persist the fine-tuned model:

```bash
docker run --gpus all -it \
  -v $(pwd)/finetuned_model:/app/finetuned_model \
  ghcr.io/tumisomokautu/zulu-classifier:latest bash
```

**Running on CPU (no GPU):**

The scripts automatically fall back to CPU if no CUDA device is found. It will be significantly slower for training but works fine for inference on short texts.

```bash
docker run ghcr.io/tumisomokautu/zulu-classifier:latest python3 scripts/test.py
```

---

### Option 2 — Docker Compose (Build Locally)

Use this if you've cloned the repo and want to build the image yourself, or if you want to make changes and test them in a container.

**Requirements:**
- Docker + Docker Compose
- NVIDIA Container Toolkit
- NVIDIA driver ≥ 550

```bash
# Clone the repo
git clone https://github.com/tumisomokautu/isizulu-ai-detector.git
cd isizulu-ai-detector

# Build and run (training)
docker compose up --build

# To run inference instead, edit docker-compose.yml and swap the command:
# command: python3 scripts/test.py
```

The `docker-compose.yml` mounts `base_model/`, `datasets/`, `finetuned_model/`, and `model_audit/` from your host into the container, so any output written during the run shows up on your machine directly.

To switch between training and inference, open `docker-compose.yml` and comment/uncomment the relevant line:

```yaml
# Train (runs tests automatically at the end):
command: python3 scripts/finetune.py
# Inference only (comment out the line above and uncomment below):
# command: python3 scripts/test.py
```

---

### Option 3 — Manual Setup (No Docker)

If you'd rather run directly on your machine without containers, this is straightforward. You'll need Python 3.10 and a CUDA-capable GPU (or just CPU for inference).

**1. Clone the repo:**

```bash
git clone https://github.com/tumisomokautu/isizulu-ai-detector.git
cd isizulu-ai-detector
```

**2. Install PyTorch (CUDA build):**

```bash
pip install torch==2.3.1 --index-url https://download.pytorch.org/whl/cu121
```

If you're on CPU only:

```bash
pip install torch==2.3.1
```

**3. Install remaining dependencies:**

```bash
pip install -r requirements.txt
```

**4. Run training:**

```bash
python3 scripts/finetune.py
```

**5. Run inference / test evaluation:**

```bash
python3 scripts/test.py
```

The first run of each script will download the required `model.safetensors` file automatically from Google Drive. After that it skips the download.

## What Each Script Does

**`scripts/finetune.py`** — full training pipeline:
1. Downloads the base model weights if not present
2. Loads and tokenizes the train + eval datasets
3. Fine-tunes the model with the config above
4. Saves the best checkpoint to `finetuned_model/final_model/`
5. Runs a final eval on both the eval set and a train subset (for overfitting check)
6. Saves metrics to `finetuned_model/metrics.json`
7. Automatically kicks off `test.py` at the end

**`scripts/test.py`** — inference + evaluation on the three test sets:
1. Downloads the fine-tuned model weights if not present
2. Loads the model from `finetuned_model/final_model/`
3. Runs batched inference over `test.jsonl`, `test2.jsonl`, `test3.jsonl`
4. Saves per-class metrics (F1, precision, recall, ROC-AUC, MCC, confusion matrix) to JSON files in `finetuned_model/`

## Hardware

Training was done on an **NVIDIA GeForce RTX 5090 (33.7 GB VRAM)**.

- Training time: 22 minutes (1,334 seconds)  
- Throughput: 186.6 samples/sec, 5.83 steps/sec

For inference only, almost any GPU (or CPU) will work — `test.py` uses batch size 16 and doesn't need much memory. For retraining, you'll want at least 16 GB VRAM with the default config. Dropping `BATCH_SIZE` to 4 in `finetune.py` gets you down to roughly 10–12 GB.
